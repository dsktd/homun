# widgetry performance review, 2026-11-21

Method: temp buffer, 1000 `widget-value-set` calls (200 for drag steps) under
`benchmark-run`. Batch = emacs-nox -Q with the package loaded from source (not
byte-compiled). Daemon = the same script via emacsclient, loaded from source
(interpreted), temp buffer, helpers unbound afterwards.

| case (ms per op)            | batch  | daemon |
|-----------------------------|--------|--------|
| slider set                  | 0.030  | 0.036  |
| vector set (3 children)     | 0.107  | 0.378  |
| toggle set                  | 0.027  | 0.170  |
| selector set                | 0.033  | 0.266  |
| button set                  | 0.023  | 0.336  |
| meter set                   | 0.031  | 0.563  |
| drag step slider            | 0.016  | 0.548  |
| drag step meter             | 0.015  | 0.547  |
| drag step selector          | 0.019  | 0.492  |
| drag step confirm button    | 0.014  | 0.494  |

Drag steps are measured through the per-step body of each drag lambda (the
mouse loop itself needs events). Batch GC: 1 to 8 collections per 1000 sets
(vector the most: it rebuilds three children). Daemon GC counts were 0
(large heap threshold); its higher numbers come from running uncompiled code.

Scaling (mixed widgets, batch / daemon), one change of a slider and of a meter
after all were created:

| widgets | create (batch/daemon) | slider change | meter change |
|---------|-----------------------|---------------|--------------|
| 10      | 0.2 ms / -            | 0.015 ms      | 0.025 ms     |
| 100     | 7.2 / 2.3 ms          | 0.021 / 0.024 | 0.031 / 0.034|
| 500     | 27 / 16.5 ms          | 0.052 / 0.043 | 0.066 / 0.059|

Redisplay was not measured: batch has no display, and no window may be created
in the daemon's frames.

## Leaks

- Overlays: 3 before and after 1000 value changes. Buffer size stable.
- Timers: a press leaves one `widgetry-button--release` timer, a hint one
  `--hint-end` timer (cancelled on confirm); all gone 0.5 s after a press
  (0 widgetry timers left).
- No marker growth observed (widget-value-set replaces the text and
  reuses the widget's own markers).

## Findings

- Each change redraws only its own widget; a vector set redraws its three
  sliders (by design: value-set rebuilds all children). A slider child change
  inside a vector redraws just that slider.
- Cost per change grows slowly with widget count (0.015 to 0.05 ms from 10 to
  500 widgets: marker adjustment in the buffer), not quadratic; creation is
  linear (~50 us per widget).
- Everything is far below a frame (16 ms); the drag paths are about 15 us per
  step compiled.

## Changes

None for performance: no clear win. (Separate, requested: slider sign column
now shows "+", and the default magnitude width is 5.)
