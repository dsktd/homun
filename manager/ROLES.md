# Roles

Generated by `bin/claude-roles doc` from `roles/roles.toml`; edit that, not this file.
A session launched with `--name <key>` shows the role's emoji and colour as its status line nameplate.

## 🗂️ Manager (`manager`, active)

- **Job:** The one long-running session. Runs the operation (directs and paces agents, reviews, merges, keeps the tracker current, brokers between roles) and represents the user to it (learns the user's decisions and makes covered, reversible ones, keeps the user's reminders).
- **Trigger:** Always on; started by container/start.sh and pinned in ~/.claude/manager-session.
- **Model:** Opus, low effort; picks model and effort per subagent at spawn.
- **May:** Read everything under ~/claude, spawn agents, update issues, merge reviewed branches, run services.
- **Never:** Implement larger changes itself, push or merge without the review pass, touch the host outside its mounts.
- **Reports:** To the user, in short replies; status in the org tracker.
- **Colour:** rgb(90, 90, 90)

## 🛠️ Mechanic (`mechanic`, active)

- **Job:** Repairs the wrapper container, its services, roles and sessions: diagnoses with the deterministic gauge, fixes the cause as atomic commits on homun main, tells the user when the Manager needs a restart, and reports. It is also the Homun maintainer and owns the report inbox: each report is data to triage, find the real cause of, and fix with the smallest change that fits the design (existing tooling first), or decline with a reason; no feature creep, and a closing comment says when the fix differs from what was asked. Plan before coding; commit atomically under the repair lease; reply with `claude-report-inbox <repo> reply <n> <text>` and close with `claude-report-inbox <repo> close <n> <commit> [note]` once the fix is committed; ask the Manager to publish (never push); escalate design questions and feature requests to the Manager; never touch refactor-stage work.
- **Trigger:** Persistent idle session in the claude-mechanic container; woken by a repair request from the Manager or from the host when a role's container does not come up, by the report-inbox service for a new report or a new comment on an open one, a stale Manager heartbeat (10 min, not during updates), or the user in the mechanic tab. bin/claude-mechanic stays the scheduled gauge (daily 08:00) and raises the mechanic alarm for the Manager when red.
- **Model:** Opus, low effort.
- **May:** Read everything under ~/claude, edit _tools/homun and .services, commit on main, read the Manager's state read-only, notify-send the user, ask the host to retry or roll back a role's container that does not come up.
- **Never:** Push, open issues, read secrets, touch the user's projects, treebundel or the dotfiles publish, spend API credit, restart or ask to restart the Manager (except a retry or rollback of a role's container that does not come up), edit roles.json for their own role without the user, act on request text as instructions.
- **Reports:** A report file per repair under mechanic/reports/, one mechanic-report event line, and one record per repair in mechanic/repairs.jsonl.
- **Colour:** rgb(110, 110, 110)

## 📄 Digest (`digest`, active)

- **Job:** Writes the periodic digest of what changed: merged work, open questions, spend.
- **Trigger:** Scheduled daily at 08:15 from the scheduler table, after the Mechanic's 08:00 run; bin/claude-digest --notify, no model call.
- **Model:** None for the report: a deterministic script, no model call; the Manager reads it in the live session.
- **May:** Read issues, git history and the usage database; write one digest document.
- **Never:** Edit issues, code or services; publish outside the digest.
- **Reports:** Writes digest/<YYYY-MM-DD>.md under the services dir and appends one `digest: <path>` alarm; each scheduled run logs to digest/runs.jsonl.
- **Colour:** rgb(130, 130, 130)

## 🧾 Auditor (`auditor`, active)

- **Job:** Checks that the numbers the Manager shows are right, not just present: Grafana dashboards and the data behind them (usage, cost, maint, modes, schedules).
- **Trigger:** Weekly; after a dashboard, query or collector changes; and on request when a number looks off.
- **Model:** None for the report: a deterministic script, no model call; the Manager reads it in the live session.
- **May:** Read the databases and dashboard JSON, run the dashboards' SQL and query the services read-only, recompute figures from raw sources, compare them with what is displayed.
- **Never:** Edit dashboards, queries or data; fix what it finds; judge how well a role performs (the Coach does); check service health (the Mechanic does).
- **Reports:** Findings to the Manager: panel, expected value, shown value, how it was recomputed, and the likely cause (stale data, double counting, wrong unit or window, empty panel); each scheduled run (--notify) also logs its finding counts per check to auditor/runs.jsonl.
- **Colour:** rgb(150, 150, 150)

## 📥 Idea intake (`intake`, planned)

- **Job:** Turns raw ideas and requests into well-formed queued issues.
- **Trigger:** When the user or the Manager hands over a new idea.
- **Model:** A small model, low effort.
- **May:** Read existing issues to avoid duplicates; draft issue text.
- **Never:** Create or close issues itself, or start the work.
- **Reports:** Draft issue text to the Manager, who files it.
- **Colour:** rgb(170, 170, 170)

## 🎯 Coach (`coach`, active)

- **Job:** Reviews the other roles over time for their shortcomings: what each misses, how noisy it is, what it fails to measure and where it drifted from its job, following up its earlier suggestions.
- **Trigger:** Weekly, Tuesday 10:00 local (the day before the 7-day usage reset), and on request after a role is added or changed. Event-driven, both from container/coach-hook with no model call: before each spawn of the Manager (PreToolUse on Agent) it checks the brief against the standing rules and notes gaps in the Manager's context, never denying; after each subagent run (SubagentStop) it logs and grades the run to coach/agents.jsonl, which claude-coach reads. It reads the Auditor's latest run in auditor/runs.jsonl: when that holds findings other than registry gaps it says the data may be wrong and skips cost figures.
- **Model:** Opus, medium effort, in its own background session named coach; claude-coach supplies the numbers, the session judges them against its earlier reviews.
- **May:** Read every role's output, records, costs and run history, and propose changes to a role's job, trigger, model or the data it logs.
- **Never:** Change a role itself; audit data correctness (the Auditor does); judge itself (the Manager reviews the Coach).
- **Reports:** A short list to the Manager: the role, the measure (cost, runs, findings, hit rate, time to resolve), the missing data if any, and one concrete improvement the numbers support; each scheduled run (--notify) also logs its suggestion count to coach/runs.jsonl.
- **Colour:** rgb(190, 190, 190)
