# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A launcher that runs one persistent "Manager" Claude Code session in a Podman container named `claude-manager`, driven from a Zellij session of the same name on the host. The container only sees `~/claude`, a treebundel workspace root (`~/claude/.bare/<repo>.git` bare clones, `~/claude/<workspace>/<repo>` worktrees), plus whatever the user mounts in later with `c mount`.

## Commands

- `./run.nu [flags]` — the launcher, a Nushell script (`#!/usr/bin/env nu`, not POSIX shell). Besides Nushell it needs Zellij, xdg-dbus-proxy, just, git and `claude-ns` on PATH; when any is missing (and `CLAUDE_WRAPPER_FLAKE` is unset, and the subcommand is not `emacs` or `usage`, which need none of them) it re-runs itself once as `nix shell path:<checkout>#deps -c nu <checkout>/run.nu <same args>` (the flake's `deps` package holds those tools), so a bare `./run.nu` or the `c` symlink works from any checkout, committed or not, as long as `nix` exists; it keeps running the checkout's own `run.nu`, so the live `container/` mount still points there. With every tool present nothing is spawned. Podman and systemd always come from the host.
- `nix run . -- [flags]` or `nix profile install .` — the same launcher as the `claude-wrapper` package, with those tools provided by the flake (its wrapper sets `CLAUDE_WRAPPER_FLAKE=1`); `nix develop` gives a shell with them plus zig.
- `just install [name] [dir]` — symlink `run.nu` as `~/.local/bin/c` (by default); an existing non-symlink is moved to `<name>.bak`.
- `just build` / `./run.nu --build` — build the container image (`podman build . -t claude`); `just update` (used by Ctrl+Space U) is the same cached build; `just refresh` rebuilds with `--no-cache` to pick up new Debian packages. Claude Code is not in the image and updates itself.
- `./run.nu -R` — replace the Zellij session (layout changes only apply to new sessions); `--restart-container` also recreates the container so a new image applies. `-s` opens a shell, `-d` only starts the container, `-Z` attaches without Zellij.
- `./run.nu --dryrun` — print the planned disk changes and podman arguments without touching anything.
- Host-only subcommands (they refuse to run inside a container):
  - `c clone <url> [name]` — bare-clone a repo into `~/claude/.bare/<name>.git`.
  - `c mount <path> [ro|rw]`, `c unmount <path>`, `c mounts` — bind host paths into the running container at the same path (read-only by default), saved in `~/.config/claude/mounts.nuon`.
  - `c port open <port>|<host>:<container>[/tcp|/udp] [from container|host] [scope host|lan]`, `c port close <spec> [from container|host]`, `c ports` — relay ports between host and container, saved in `~/.config/claude/ports.nuon`. Options are iproute2-style keyword/value pairs (`lib/keywords.nu`): by default the host's port reaches the container; `from host` reverses that; `scope lan` binds the host side to 0.0.0.0 instead of 127.0.0.1 so the LAN reaches the container's port (not with `from host`). A relay's unit name ignores its scope, so reopening one with another scope replaces it and `port close` needs no scope.
  - `c emacs [<file> [<line>]]` — a frame (without a file it starts on the Manager's focus, else the dashboard) of Claude's Emacs (the `emacs` service, below) on this display with the host's own `emacsclient -n -c` against `~/claude/.services/emacs/socket/server`, starting the service through `podman exec` first when the socket is missing (the first start installs Emacs into the Nix profile, so it may say to retry). Runs `bin/claude-emacs frame`; Ctrl+Space e does the same from Zellij.
  - `c usage [--since <duration>] [-n <rows>] [-w <width>] [--json]` — summarise `~/.local/share/claude/claude/usage.jsonl` (the samples statusline.sh appends): latest budgets, a table of the last samples and per-day sparklines of the 5-hour, 7-day and context budgets left. Runs `bin/claude-usage`, which also works inside the container against `~/.claude/usage.jsonl`. `bin/claude-usage db cost [--by day|session|model|agent] [--source samples|transcripts] [--since <duration>] | sql "<statement>"` query the SQLite the `usage-db` service keeps at `~/claude/.services/usage-db/usage.sqlite` (same path on the host): `--source samples` (the default) is the status line's cost estimate, `--source transcripts` prices every API message of the session transcripts, subagents included (`--by agent`). `bin/claude-usage forecast [--since <duration>] [--history <file>] [--json]` prints the usage-db's forecast (`forecast.py`; the same numbers as the page's Forecast section): burn rates, Manager/agent split, projection to both resets, the resource mode and the agent slots it allows (0-3), Cal's activity profile and the leftover-burn allowance; it needs `python3`. `bin/claude-usage db budget [--by session|model|hour] [--since <duration>]` shows what used up the 5-hour window (the `budget_deltas` view: the rise in `five_hour_used` between consecutive samples, attributed to the sample's session).
  - `bin/claude-pane-log <name> <command> [args...]` (POSIX sh) — runs a command with its terminal attached under `script -q -e -c`, recording the output to `${CLAUDE_LOG_DIR:-~/claude/.logs}/pane-<name>-<YYYYmmdd-HHMMSS>.log` (dir mode 700; name `[a-z0-9-]+`, else exit 2; the command's exit status is kept; without `script` it runs the command and says logging is off). Each run keeps the newest 10 logs per name and deletes any older than 7 days. `show <name>` prints the newest log with escapes, CRs and script's header/footer stripped; `list` shows logs newest first with sizes. The zellij `Run` binds for claude-update (`update`), claude-changelog (`changelog`) and claude-wrapper-keys (`keys`), and the changelog pane `claude-update` opens, go through it, so the Manager can read a pane's error afterwards. The screensaver tab is not logged (its output is full-screen frames).
  - `just snap [label]`, `snaps`, `snap-restore <id> [dest]`, `snap-delete <id>`, `snap-prune [keep] [keep-pre]` (only unlabelled ids count toward `keep`; other labels are never pruned), `snap-enable` — read-only bcachefs snapshots of `~/claude` (needs it to be a subvolume) into `${CLAUDE_SNAPDIR:-~/library/backup/dsktd/claude}/<UTC>[-label]`; restore copies to `~/claude-restore/<id>`, never in place. `snap-enable` tests a snapshot and creates the marker `~/.config/claude/snapshots`; while it exists `run.nu` takes a `pre-recreate` snapshot after preflight and before stopping the old container, and aborts the restart if that fails. Snapshots run `sudo -n` (never a prompt), so they need a NOPASSWD sudoers rule for `bcachefs subvolume snapshot`/`delete` (rule and conversion steps are in the justfile comment); `snap-enable` fails early without it.
  - `bin/ghd <gh args>` — `gh` with the dsktd org token from `~/.config/gh/dsktd.token` (resource owner dsktd; the desocketed login stays the default `gh`). `GHD_TOKEN_FILE` overrides the path.
  - `bin/claude-sched add <name> cron "<expr>" prompt "<text>" [target live|headless|auto] [catchup once|skip] [budget <pct>] [model <m>] | del|show|enable|disable|run <name> | list` — the persistent schedule table, `~/claude/.services/sched/schedules.nuon` (`CLAUDE_SCHED_DIR` overrides the directory), written atomically; names are kebab-case and unique, the cron expression has 5 numeric fields. After every change it sends SIGHUP to the process group in `~/claude/.services/scheduler/pid` (the `scheduler` service), if there is one. `run <name>` asks the service (`SCHEDULER_URL`, default `http://127.0.0.1:8424`) to fire the schedule now, ignoring cron, enabled and budget.
  - `bin/claude-mechanic [--json] [--notify]` — python3 stdlib, deterministic health check: prints only red findings (`<check>: <what>`), nothing when green, exit 0. Checks: services, logs (every service `log` and every registry log entry's `path`, file or directory, over 8 MB), usage-db lag, maint, disk, scheduler events size, schedules (an enabled one has not fired in 1.5 times the longest gap between its next 3 fires, from `scheduler/history.jsonl`; one that never fired counts from its `created`, else the table's mtime); paths via `CLAUDE_SERVICES_DIR`, `SCHEDULER_DIR`, `CLAUDE_SCHED_DIR`, `REGISTRY_DIR`, `MAINT_DB`, `MECHANIC_ROOT`. `--notify` appends the fixed `mechanic` alarm to the scheduler events file only when there are findings. With `--notify` (the scheduled form; a manual run logs nothing) it also appends `{ts, findings, checks}` (counts per check, no text) to `mechanic/runs.jsonl` under the services dir (`MECHANIC_RUNS`), kept to the last 2000 lines above 1 MB. Tests: `tests/py/test_mechanic.py`.
  - `bin/claude-auditor [--json] [--notify]` — python3 stdlib, deterministic audit of the numbers the dashboards show: prints only red findings (`<check>: <what>`), nothing when green, exit 0. Checks: every SQL panel in `container/services/graphs/dashboards/*.json` run read-only over 7 days (errors, empty, negative or NaN, stale series), cost and token panel totals vs the raw tables (1%), duplicate keys and unpriced messages, table freshness, order (and for `agent_runs` `last_seen` freshness) and row counts, including the untimed `meta`, `prices` and `transcripts`, that dropped since the last audit (state file `state.json` in `AUDITOR_DIR`, default `~/claude/.services/auditor`), active roles that leave no records (the Manager's messages counted over the last 7 days), the newest 200 scheduler events lines whose alarm is neither a registered alarm nor a `[schedule <name>]` fire (`alarms: unknown alarm <name>`), and the registry (`registry: <kind>-<name> exists but is not registered | is registered but missing | has no checker`). Paths via `REGISTRY_DIR`, `CLAUDE_SCHED_DIR`, `CLAUDE_SERVICES_DIR`, `SCHEDULER_DIR`, `MAINT_DB`, `AUDITOR_DASHBOARDS`, `AUDITOR_ROLES`. A database, file or `nu` error ends the audit as one `audit: <error>` finding (the run is still logged). `--notify` appends the fixed `auditor` alarm to the scheduler events file only when there are findings, and logs the run as `{ts, findings, checks}` to `auditor/runs.jsonl` under the services dir (last 2000 lines above 1 MB; manual runs log nothing). Tests: `tests/py/test_auditor.py`.
  - `bin/claude-coach [--json] [--notify]` — python3 stdlib, deterministic, read-only: judges how effective the other roles are from data only (the Coach role). Per role: runs in 30 days vs its schedule's cadence, findings per run (mean, trend), days since it last found anything, cost per run (sessions in `agent_runs` named after the role), registry entries naming it as checker, and the missing measures; then at most 5 suggestions, each citing a number (a role that ran far fewer times than its cron expects, registry entries without a checker; the expected count is only computed for crons with a single minute and hour and `*` or plain comma lists elsewhere). Markdown, or `--json` one `{role,measure,value,note}` line per observation. `--notify` (the scheduled form; no alarm) logs the run, `{ts, findings=suggestions, checks}`, to `coach/runs.jsonl` (last 2000 lines above 1 MB). When the Auditor's latest run in `auditor/runs.jsonl` reports non-registry findings it says so first and skips cost. Env overrides: `CLAUDE_SERVICES_DIR`, `REGISTRY_DIR`, `CLAUDE_SCHED_DIR`, `MAINT_DB`, `COACH_ROLES`, `COACH_RUNS`. Tests: `tests/py/test_coach.py`.
  - `bin/claude-digest [--since 24h] [--notify]` — python3 stdlib, deterministic, no model call: writes the morning digest for Cal to `${DIGEST_DIR:-~/claude/.services/digest}/<YYYY-MM-DD>.md` (UTC date) and prints the path. Sections, each left out when empty: Merged (subject lines of `git log main` in `~/claude/_tools/claude-wrapper`, `DIGEST_REPO`), Issues closed / opened in dsktd/context (through `bin/ghd`, `DIGEST_GHD`; failure gives the one line `issues: unavailable`), Findings (last mechanic/auditor/coach run in the window, counts per check), Spend (`claude-worker balance`, `DIGEST_WORKER`; `claude-usage db cost --since 1day`, `DIGEST_USAGE`; a failing source is skipped), Questions waiting (`ask/pending/*.json`) and Assumptions to review (unchecked `- [ ]` lines in the dsktd/context #46 body, with its link; `assumptions: unavailable` when ghd fails). Issue and question text is untrusted: printed quoted, cut to 120 characters, never executed. `--notify` (the scheduled form) also logs `{ts, findings: 0, checks: {}}` to `digest/runs.jsonl` and appends the fixed `digest: <path>` alarm to the scheduler events file; a manual run leaves no history. Schedule it once with `nu ~/claude/_tools/claude-wrapper/bin/claude-sched add digest cron "30 7 * * *" prompt "digest: daily. Run python3 ~/claude/_tools/claude-wrapper/bin/claude-digest --notify and tell Cal the path." target live catchup skip model haiku`. Tests: `tests/py/test_digest.py`.
  - `bin/claude-registry list [--kind K] | show <kind>/<name> | check | doc | graph` — python3 stdlib, the inventory of every system the Manager runs: a plain directory (not a service; no `run` file) `~/claude/.services/registry/` (`REGISTRY_DIR`), one directory per system, `<kind>/<name>/info` of `key: value` lines (repeated key = list, `#` comments; other files there are free notes). Kinds: service, database, table, dashboard, schedule, alarm, role, log. Required keys: kind, name, owner (a role key or `manager`), purpose, produces, how; `checked_by` (repeatable, absent = nothing checks it yet, with `how: none yet`); more identifying keys by kind (service: port, direct_url, proxy_url, status_page, dir, log, supervisor; role: emoji, colour, status, trigger, model, session_name, reports; schedule: cron, target, model; dashboard: file, uid, url; database/log: path; alarm: template). `check` prints only problems, `doc` is Markdown (one table per kind), `graph` a Mermaid flowchart. The Auditor's `registry:` findings compare it with the real services, tables, dashboards, schedules and roles and flag entries without a checker. Tests: `tests/py/test_registry.py`.
  - `bin/claude-worker run <name> <agent-type> <worktree> <prompt-file> [--model M] [--cap USD]` (python, stdlib; also `list`, `balance`) — runs one headless agent on the pay-per-token API credit instead of the subscription: `claude -p --agents <file built from ~/.claude/agents/<type>.md> --agent <type> --max-budget-usd <cap, default 2; must be finite, above 0 and at most the daily cap> --output-format json --permission-mode acceptEdits --permission-prompts none --allowedTools "Read Write Edit Grep Glob Bash(git *) Bash(python3 *) Bash(python *) Bash(nu *) Bash(ruff *) Bash(black *) Bash(nix shell *) Bash(just *) Bash(chmod *) Bash(ls *) Bash(pwd) Bash(timeout *)" --disallowedTools "WebFetch WebSearch Bash(git push*) Bash(git remote*)" --no-session-persistence --add-dir <worktree>`, prompt on stdin, cwd the worktree, with `CLAUDE_CONFIG_DIR=~/claude/.services/workers/.config` (an empty config dir: no OAuth login, so only the API key can authenticate and the subscription is never billed, and no settings, hooks or memory leak in). The allowlist is not a sandbox: python3, nu, nix shell and git run arbitrary code, so a prompt-injected agent can read the key; after a run the worktree's changes since the starting commit and its new files are scanned for key-like strings, and a hit sets `leak_suspected: true` in the ledger row and prefixes the events line with `LEAK SUSPECTED`. Run names ending in `.tmp` or `.json` are refused. `ANTHROPIC_API_KEY` comes from `~/.config/anthropic/api.key` (`CLAUDE_WORKER_KEY_FILE`) and is set only in that child's environment (OAuth variables are dropped; the key never reaches a command line, and key-looking strings are redacted from everything written). Refuses a bad or reused run name, a missing worktree, prompt or agent, when today's (UTC) spend plus the cap exceeds `CLAUDE_WORKER_DAILY_CAP` (10) or when the recorded balance would go negative. Under a lock it reserves the cap in the ledger and balance (`estimate: true`) before starting and settles to the real `total_cost_usd` afterwards, so parallel workers cannot overshoot and a crashed run stays charged at the cap. Writes `~/claude/.services/workers/<name>/{result.txt,result.json,stderr.txt}`, appends to `ledger.jsonl`, decrements `balance.json` (created from `CLAUDE_WORKER_START_BALANCE`, 99.62) and appends a `worker` alarm line to `scheduler/events` if that exists. `CLAUDE_WORKER_{DIR,EVENTS,AGENTS,CLAUDE}` are test seams.

`just test` (`nu tests/run.nu`) lints every script and drives run.nu's subcommands, `container/start.sh` and `bin/claude-attach` in a throwaway HOME against `tests/fake` standing in for `podman`, `systemd-run`, `systemctl`, `git`, `claude` and `claude-update` (and `zellij`, `just` and `nix` where the flake bootstrap is tested), asserting on the calls they log; it also drives `container/services.sh` against a fake `~/claude/.services` tree (real `sleep` services, stopped afterwards), the `usage-db` importer against a synthetic `usage.jsonl` and synthetic transcripts (with `container/usage-hook.sh`), and the proxy's Caddyfile generation (validated with `caddy`, via `nix shell` when it is not on PATH); `container/emacs/` loaded by a bare `emacs --batch` (`nixpkgs#emacs-nox` through `nix shell` when none is on PATH; skipped without `nix`), exercising `claude-ask` end to end; `bin/claude-emacs` against a fake `emacsclient` (which answers `ask` on its own); `c emacs` against the fake podman. `container/request-update.sh` is tested end to end with start.sh as PID 1 under `unshare -Urpf --mount-proc` (skipped where user namespaces are unavailable). `CLAUDE_WRAPPER_CONTAINERENV` points `host-only` at a different marker file, so the suite also runs inside the container, and the sandbox sets `CLAUDE_WRAPPER_FLAKE` so run.nu does not bootstrap through the real `nix`. Run it after every change.

`python3 -m unittest discover -s tests/py -p 'test_*.py'` runs the fast stdlib-only Python tests (scheduler `serve.py`, `bin/claude-worker`, scheduler `listen`, `container/claude-busy`, the `tally/slots` screensaver, and the dashboards' SQL panels against a copy of `usage.sqlite` named by `DASH_DB`, skipped without it; no network, a temp dir only, a few seconds); keep them `ruff check` and `black` clean.

## Architecture

- **Containerfile** — Debian image with git, gh, nix, notify-send and Nushell (a pinned static release tarball in `/usr/local/bin`, since `/nix` is a volume at runtime; `SHELL` and root's login shell). Tools installed with `nix profile install --profile /nix/var/nix/profiles/default <pkg>` land in the persistent `claude-nix` volume and are on PATH in every container. The scripts that run inside the container live in `container/`, copied to `/opt/claude-wrapper` in the image (ENTRYPOINT, CMD and the managed status line point there); `run.nu` bind-mounts the checkout's `container/` read-only over that copy, so edits apply on the next container start (the status line on its next refresh) without a rebuild, while the image's copy keeps it usable without the launcher. Claude Code is not in the image: `container/entrypoint.sh` runs the official installer on first start (under a `flock`, so concurrent starts are safe) into the shared `claude-code`/`claude-code-bin` volumes (`~/.local/share/claude`, `~/.local/bin`), where its own auto-updater maintains it. On every start it also installs Nushell into that default profile if missing, and seeds the persisted global git config (`~/.config/git/config`, which `prepare` pre-creates so `--global` picks it over an absent `~/.gitconfig`) with a git identity from the gh login (`<login>@users.noreply.github.com`) when it has none. The container's main process is `container/start.sh` (the image's CMD; it appends `container/identity.md`, the Manager's name, pronouns and personality (the user is Cal there), to the Manager's system prompt on every start, because the seeded `~/claude/CLAUDE.md` is never overwritten): it resumes the conversation the user last typed in (`--resume`), falling back to `claude --continue || claude`; a session id in `~/.claude/manager-session` pins which one it opens. Every start passes Claude a first prompt that tells the Manager to arm the scheduler monitor (see `manager/CLAUDE.md`), which is why it never `claude attach`es to a background job (an attach cannot take a prompt). It reads the last `history.jsonl` entry, a Claude Code internal, so it is the first thing to check when an update changes startup behaviour.
- **container/request-update.sh** — what the Manager runs to update from inside: SIGUSR1 to PID 1 (start.sh traps it and exits 75 once the foreground Claude has returned, instead of starting another), then SIGTERM to every other process in the container. It refuses while PID 1 is still `entrypoint.sh` (installing Claude Code), where there is no trap yet, and, unless called with `--force`, while `claude-busy` lists work in progress (exit 1, nothing killed). **container/claude-busy** (python stdlib; the image's `/usr/local/bin/claude-busy` shim runs it with the Nix profile's `python3`, exiting 0 with a note when there is none) prints one line per running background agent (`claude agents --json --all`: `kind` background and a `state` other than done, failed or stopped; the interactive Manager is not work) and per `claude-worker` run in flight (a ledger row with `exit` null and a live `claude-worker run <name>` process in /proc, so a crashed run's leftover reservation does not count); idle is silent exit 0, busy exit 1, and a probe that cannot run (no `claude`, unparseable output or ledger) notes it on stderr and does not block. `CLAUDE_BUSY_CLAUDE` and `CLAUDE_BUSY_PROC` are test seams. `bin/claude-update` runs it through `podman exec` first and, when busy, lists the work and asks `Update anyway? [y/N]` on the pane (anything but `y` exits without touching the marker or the container); a container that does not answer is not asked about. `bin/claude-attach` reads the 75 with `podman inspect` from the stopped container (`run.nu` starts it without `--rm` because `podman attach` returns 0 whatever the container exited with), runs `claude-update` and reattaches like after Ctrl+Space U (or exits 75 itself when run outside a Zellij session, where there is no `claude-update`).
- **container/statusline.sh** — the status line, short and contextual: a nameplate (yellow `🧮 Tally` for the session pinned in `~/.claude/manager-session`, blue `🤖 <session_name>` (or `agent`) for any other, except a session named after a role, see Roles) and the model, then only the segments that matter, in priority order and dropped from the end when the width budget (`$COLUMNS`, else 100) runs out: Manager-only `❓N` (questions), `⚙N` (agents), `API $x`, the resource mode (`🔥`/`🧊`/`⏸`, `*` when overridden, hidden for `normal`) and `sN` (agent slots) read from usage-db's `mode` file (hidden when missing or older than 30 minutes); the used budgets `N%/5h N%/wk` only once either is at 50% or more, plus `↻<time>` to the 5h reset above 70%; the git branch; `ctxN%` context used; cost `$x` from $1 up. It also appends throttled usage samples (rate limits, context, cost) to `~/.claude/usage.jsonl` for graphing; per-session throttle state is in `~/.claude/usage/`.
- **container/services.sh** — the service supervisor, `claude-services` in the image (a shim that runs this file via `sh`). Each `~/claude/.services/<name>/` with an executable `run` is a service: `start` writes a generated entry (a `run` that sources `env`, appends output to `log` (emptied before a run when above 10 MB), writes `pid` and `exec`s `chpst -P ./run` so the service leads its own process group; a `finish` that pauses 2 s unless the service was stopped on purpose) into the scan directory `/run/claude-services` (`CLAUDE_SERVICES_SCAN`) and `sv up`s it; `claude-services supervise` is `runsvdir` on that directory, started in the background by `start` when no runsvdir watches the scan directory (a /proc cmdline match), so a dead one comes back on the next start (runit comes from Debian's `runit` package; runsvdir rescans every 5 s, so a first start waits up to 8 s for runsv). `pid` is the service's own process (group); `list` reads state from `sv status` (a crash pause reads as stopped). `stop` writes runit's `down` file (so a restarted runsv leaves it down; `start` removes it) and is `sv down` plus SIGTERM to the process group, then SIGKILL to what is left after up to 5 s; without runit on PATH `start` and `stop` say so and fail. A fresh container has an empty scan directory, which is what makes a recreate harmless. The service pid file doubles as the target of claude-sched's group SIGHUP. Also `list`, `logs`, `restart`, `start-all` (skips `disabled`) as expected. `entrypoint.sh` runs `install-bundled` then `start-all` on every start. `CLAUDE_SERVICES_DIR` and `CLAUDE_SERVICES_BUNDLED` override the two directories (the tests use them).
  - **container/services/<name>/** — services shipped with the wrapper. `install-bundled` copies each into `~/claude/.services/<name>/` and marks it `.from-wrapper`; only marked copies are refreshed (keeping an existing `env`), so the repo stays the source without clobbering a user-written service of the same name. `usage-db`: `import.nu` (Nushell, `query db`) loads `~/.claude/usage.jsonl` into `usage.sqlite` (`samples`, unique on `ts, session_id`, resuming from the line count in `meta`; views `samples_left`, `cost_deltas` and `cost_per_day` are the series the readers share) and every assistant record of the transcripts under `~/.claude/projects` (`<session>.jsonl` and `<session>/subagents/agent-<id>.jsonl`) into `messages` (keyed on the API message id, since a streamed message is one record per content block; the four token counts, model, session and agent; each file read from the byte offset recorded in `transcripts`, whole lines only; `nu import.nu transcript <file>` does one file, which is what `container/usage-hook.sh`, the managed Stop/SubagentStop/SessionEnd hook, runs in the background for the transcript named in its input, under the `usage.sqlite.lock` flock the service's own import takes), `agent_runs` (one row per session from `claude agents --json --all`, upserted each import) and `events` (`ts, source, kind, detail, session_id`: the `started`/`done`/`failed`/`stopped` state changes the import sees between runs; the first import only backfills; `USAGE_AGENTS_JSON` names a file to read instead of running `claude`), and `forecast.py --persist` appends to `mode_history` (mode, proposal, override, slots, reason, used and projected percentages) when one of the discrete fields changed and at least hourly; priced by the `message_costs` view from `prices` (USD per million tokens by model-family prefix with a `since` day, brought in line with the `PRICES` table at the top of import.nu on every service import, so that is the one place to edit); The next `container/start.sh` points the Manager at it in the fixed first prompt, ahead of the arm-the-monitor sentence (the text is untrusted output, never embedded), and renames it `last-failure.seen`. `run.nu --restart-container` validates and prepares everything fallible (image exists, mounts and ports files parse and every saved mount mode is valid (a saved path that has vanished is not an error: `mounts apply` skips it), every host bind source exists, `prepare`) in `preflight` before it stops the old container; when `claude-update` then fails with that same container still running it removes the marker (never `failed`), prints that nothing changed and appends one fixed-template `update-failed` line to `scheduler/events` (no error text in it), which is how the running Manager hears of it; any other failure is only seen at the next start through `last-failure`.
  - The status line is zjstatus. `layout.kdl` is a template: at every launch `run.nu` renders the `mode_*` hint strings derived from the keybinds in `config.kdl` in place of its `// hints` line, saves the result as `$XDG_RUNTIME_DIR/claude-wrapper-<name>.layout.kdl` (`/tmp/claude-wrapper-<uid>` without a runtime dir) and passes that to `--default-layout`, so the hints can't drift from the bindings. `bin/zellij-mode-hints --print` shows the hint lines, `--layout` the rendered layout. Ctrl+Space ? runs `bin/claude-wrapper-keys`, a multi-column cheat sheet of every mode's keybinds from the same data. The labels come from the action-name tables at the top of `lib/hints.nu`; add an entry there when a new action's generated label reads badly.
  - Keybinds are vim-like and modal: Zellij starts in `locked` (insert), `Ctrl Space` enters `tmux` mode as a normal mode, `Esc`/`i` return. They replace Zellij's defaults (`clear-defaults=true`), so every mode used must be bound in full.
- **flake.nix** — packages `run.nu` with its host-side dependencies as a wrapper that sets `CLAUDE_WRAPPER_FLAKE=1`, and exposes them alone as `packages.deps` (a `buildEnv`), which `run.nu` fetches on its own when one is missing. Flakes only see git-tracked files: `git add` new files before `nix build`/`nix run`.

## Roles

`container/roles.json` is the one registry of roles (Manager = Tally, Mechanic, Auditor, Coach, Digest writer, and the planned Idea intake): per key `name`, `status` (`active`/`planned`), `emoji`, `colour` (RGB triple, dark text on it), `job`, `trigger`, `model`, `may`, `never`, `reports`. `bin/claude-roles list | show <key> | doc` reads it; `manager/ROLES.md` is the committed output of `doc` (a test fails when they differ), so edit the registry and regenerate: `bin/claude-roles doc > manager/ROLES.md`. To add a role, add an entry with a unique emoji, name and colour. A role session gets its nameplate from `container/statusline.sh` by launching it with `--name <key>` (case-insensitive; `<key>-<suffix>` and `<key>:<suffix>` also match); the pinned Manager session always stays Tally, and a missing or invalid registry or an unknown name keeps the blue `🤖 <session_name>` plate.
