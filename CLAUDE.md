# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A launcher that runs one persistent "Manager" Claude Code session in a Podman container named `claude-manager`, driven from a Zellij session of the same name on the host. The container only sees `~/claude`, a treebundel workspace root (`~/claude/.bare/<repo>.git` bare clones, `~/claude/<workspace>/<repo>` worktrees), plus whatever the user mounts in later with `c mount`.

## Commands

- `./run.nu [flags]` — the launcher, a Nushell script (`#!/usr/bin/env nu`, not POSIX shell). Besides Nushell it needs Zellij, xdg-dbus-proxy, just, git and `claude-ns` on PATH; when any is missing (and `CLAUDE_WRAPPER_FLAKE` is unset, and the subcommand is not `emacs` or `usage`, which need none of them) it re-runs itself once as `nix shell path:<checkout>#deps -c nu <checkout>/run.nu <same args>` (the flake's `deps` package holds those tools), so a bare `./run.nu` or the `c` symlink works from any checkout, committed or not, as long as `nix` exists; it keeps running the checkout's own `run.nu`, so the live `container/` mount still points there. With every tool present nothing is spawned. Podman and systemd always come from the host.
- `nix run . -- [flags]` or `nix profile install .` — the same launcher as the `claude-wrapper` package, with those tools provided by the flake (its wrapper sets `CLAUDE_WRAPPER_FLAKE=1`); `nix develop` gives a shell with them plus zig.
- `just install [name] [dir]` — symlink `run.nu` as `~/.local/bin/c` (by default); an existing non-symlink is moved to `<name>.bak`.
- `just build` / `./run.nu --build` — build the container image (`podman build . -t claude`); `just update` (used by Ctrl+Space U) is the same cached build; `just refresh` rebuilds with `--no-cache` to pick up new Debian packages. Claude Code is not in the image and updates itself.
- `./run.nu -R` — replace the Zellij session (layout changes only apply to new sessions); `--restart-container` also recreates the container so a new image applies. `-s` opens a shell, `-d` only starts the container, `-Z` attaches without Zellij.
- `./run.nu --dryrun` — print the planned disk changes and podman arguments without touching anything.
- Host-only subcommands (they refuse to run inside a container):
  - `c clone <url> [name]` — bare-clone a repo into `~/claude/.bare/<name>.git`.
  - `c mount <path> [ro|rw]`, `c unmount <path>`, `c mounts` — bind host paths into the running container at the same path (read-only by default), saved in `~/.config/claude/mounts.nuon`.
  - `c port open <port>|<host>:<container>[/tcp|/udp] [from container|host] [scope host|lan]`, `c port close <spec> [from container|host]`, `c ports` — relay ports between host and container, saved in `~/.config/claude/ports.nuon`. Options are iproute2-style keyword/value pairs (`lib/keywords.nu`): by default the host's port reaches the container; `from host` reverses that; `scope lan` binds the host side to 0.0.0.0 instead of 127.0.0.1 so the LAN reaches the container's port (not with `from host`). A relay's unit name ignores its scope, so reopening one with another scope replaces it and `port close` needs no scope.
  - `c emacs [<file> [<line>]]` — a frame of Claude's Emacs (the `emacs` service, below) on this display with the host's own `emacsclient -n -c` against `~/claude/.services/emacs/socket/server`, starting the service through `podman exec` first when the socket is missing (the first start installs Emacs into the Nix profile, so it may say to retry). Runs `bin/claude-emacs frame`; Ctrl+Space e does the same from Zellij.
  - `c usage [--since <duration>] [-n <rows>] [-w <width>] [--json]` — summarise `~/.local/share/claude/claude/usage.jsonl` (the samples statusline.sh appends): latest budgets, a table of the last samples and per-day sparklines of the 5-hour, 7-day and context budgets left. Runs `bin/claude-usage`, which also works inside the container against `~/.claude/usage.jsonl`. `bin/claude-usage db cost [--by day|session|model|agent] [--source samples|transcripts] [--since <duration>] | sql "<statement>"` query the SQLite the `usage-db` service keeps at `~/claude/.services/usage-db/usage.sqlite` (same path on the host): `--source samples` (the default) is the status line's cost estimate, `--source transcripts` prices every API message of the session transcripts, subagents included (`--by agent`). `bin/claude-usage forecast [--since <duration>] [--history <file>] [--json]` prints the usage-db's forecast (`forecast.py`; the same numbers as the page's Forecast section): burn rates, Manager/agent split, projection to both resets, the resource mode and the agent slots it allows (0-3), the Prime's activity profile and the leftover-burn allowance; it needs `python3`. `bin/claude-usage db budget [--by session|model|hour] [--since <duration>]` shows what used up the 5-hour window (the `budget_deltas` view: the rise in `five_hour_used` between consecutive samples, attributed to the sample's session).
  - `bin/ghd <gh args>` — `gh` with the dsktd org token from `~/.config/gh/dsktd.token` (resource owner dsktd; the desocketed login stays the default `gh`). `GHD_TOKEN_FILE` overrides the path.
  - `bin/claude-sched add <name> cron "<expr>" prompt "<text>" [target live|headless|auto] [catchup once|skip] [budget <pct>] [model <m>] | del|show|enable|disable|run <name> | list` — the persistent schedule table, `~/claude/.services/sched/schedules.nuon` (`CLAUDE_SCHED_DIR` overrides the directory), written atomically; names are kebab-case and unique, the cron expression has 5 numeric fields. After every change it sends SIGHUP to the process group in `~/claude/.services/scheduler/pid` (the `scheduler` service), if there is one. `run <name>` asks the service (`SCHEDULER_URL`, default `http://127.0.0.1:8424`) to fire the schedule now, ignoring cron, enabled and budget.
  - `bin/claude-worker run <name> <agent-type> <worktree> <prompt-file> [--model M] [--cap USD]` (python, stdlib; also `list`, `balance`) — runs one headless agent on the pay-per-token API credit instead of the subscription: `claude -p --bare --agents <file built from ~/.claude/agents/<type>.md> --agent <type> --max-budget-usd <cap, default 2> --output-format json --permission-mode acceptEdits --permission-prompts none --allowedTools <Bash git/python/nu/ruff/black/nix shell/just> --disallowedTools "WebFetch WebSearch" --no-session-persistence --add-dir <worktree>`, prompt on stdin, cwd the worktree. `ANTHROPIC_API_KEY` comes from `~/.config/anthropic/api.key` (`CLAUDE_WORKER_KEY_FILE`) and is set only in that child's environment (OAuth variables are dropped; the key never reaches a command line, and key-looking strings are redacted from everything written). Refuses a bad or reused run name, a missing worktree, prompt or agent, when today's (UTC) spend plus the cap exceeds `CLAUDE_WORKER_DAILY_CAP` (10) or when the recorded balance would go negative. Under a lock it reserves the cap in the ledger and balance (`estimate: true`) before starting and settles to the real `total_cost_usd` afterwards, so parallel workers cannot overshoot and a crashed run stays charged at the cap. Writes `~/claude/.services/workers/<name>/{result.txt,result.json,stderr.txt}`, appends to `ledger.jsonl`, decrements `balance.json` (created from `CLAUDE_WORKER_START_BALANCE`, 99.62) and appends a `worker` alarm line to `scheduler/events` if that exists. `CLAUDE_WORKER_{DIR,EVENTS,AGENTS,CLAUDE}` are test seams.

`just test` (`nu tests/run.nu`) lints every script and drives run.nu's subcommands, `container/start.sh` and `bin/claude-attach` in a throwaway HOME against `tests/fake` standing in for `podman`, `systemd-run`, `systemctl`, `git`, `claude` and `claude-update` (and `zellij`, `just` and `nix` where the flake bootstrap is tested), asserting on the calls they log; it also drives `container/services.sh` against a fake `~/claude/.services` tree (real `sleep` services, stopped afterwards), the `usage-db` importer against a synthetic `usage.jsonl` and synthetic transcripts (with `container/usage-hook.sh`), and the proxy's Caddyfile generation (validated with `caddy`, via `nix shell` when it is not on PATH); `container/emacs/` loaded by a bare `emacs --batch` (`nixpkgs#emacs-nox` through `nix shell` when none is on PATH; skipped without `nix`), exercising `claude-ask` end to end; `bin/claude-emacs` against a fake `emacsclient` (which answers `ask` on its own); `c emacs` against the fake podman. `container/request-update.sh` is tested end to end with start.sh as PID 1 under `unshare -Urpf --mount-proc` (skipped where user namespaces are unavailable). `CLAUDE_WRAPPER_CONTAINERENV` points `host-only` at a different marker file, so the suite also runs inside the container, and the sandbox sets `CLAUDE_WRAPPER_FLAKE` so run.nu does not bootstrap through the real `nix`. Run it after every change.

## Architecture

- **Containerfile** — Debian image with git, gh, nix, notify-send and Nushell (a pinned static release tarball in `/usr/local/bin`, since `/nix` is a volume at runtime; `SHELL` and root's login shell). Tools installed with `nix profile install --profile /nix/var/nix/profiles/default <pkg>` land in the persistent `claude-nix` volume and are on PATH in every container. The scripts that run inside the container live in `container/`, copied to `/opt/claude-wrapper` in the image (ENTRYPOINT, CMD and the managed status line point there); `run.nu` bind-mounts the checkout's `container/` read-only over that copy, so edits apply on the next container start (the status line on its next refresh) without a rebuild, while the image's copy keeps it usable without the launcher. Claude Code is not in the image: `container/entrypoint.sh` runs the official installer on first start (under a `flock`, so concurrent starts are safe) into the shared `claude-code`/`claude-code-bin` volumes (`~/.local/share/claude`, `~/.local/bin`), where its own auto-updater maintains it. On every start it also installs Nushell into that default profile if missing, and seeds the persisted global git config (`~/.config/git/config`, which `prepare` pre-creates so `--global` picks it over an absent `~/.gitconfig`) with a git identity from the gh login (`<login>@users.noreply.github.com`) when it has none. The container's main process is `container/start.sh` (the image's CMD): it resumes the conversation the user last typed in (`--resume`), falling back to `claude --continue || claude`; a session id in `~/.claude/manager-session` pins which one it opens. Every start passes Claude a first prompt that tells the Manager to arm the scheduler monitor (see `manager/CLAUDE.md`), which is why it never `claude attach`es to a background job (an attach cannot take a prompt). It reads the last `history.jsonl` entry, a Claude Code internal, so it is the first thing to check when an update changes startup behaviour.
- **container/request-update.sh** — what the Manager runs to update from inside: SIGUSR1 to PID 1 (start.sh traps it and exits 75 once the foreground Claude has returned, instead of starting another), then SIGTERM to every other process in the container. It refuses while PID 1 is still `entrypoint.sh` (installing Claude Code), where there is no trap yet. `bin/claude-attach` reads the 75 with `podman inspect` from the stopped container (`run.nu` starts it without `--rm` because `podman attach` returns 0 whatever the container exited with), runs `claude-update` and reattaches like after Ctrl+Space U (or exits 75 itself when run outside a Zellij session, where there is no `claude-update`).
- **container/statusline.sh** — the status line (`🧮 Tally` badge for the session pinned in `~/.claude/manager-session`, any other session shows `🤖` and its `session_name` (or `agent`) instead; model, context left, rate limits left, preceded by the resource mode badge `🔥 burn`/`normal`/`🧊 frugal`/`⏸ hold`, `*` when overridden, then `slots N` (agent slots now allowed, after the 7d pace cap), read from usage-db's `mode` file and hidden when it is missing or older than 30 minutes). It also appends throttled usage samples (rate limits, context, cost) to `~/.claude/usage.jsonl` for graphing; per-session throttle state is in `~/.claude/usage/`.
- **container/services.sh** — the service supervisor, `claude-services` in the image (a shim that runs this file via `sh`). Each `~/claude/.services/<name>/` with an executable `run` is a service: `start` forks a `setsid` loop that re-runs `run` (after sourcing `env`) with its output appended to `log` (emptied before a run when it is above 10 MB; a long-running service can outgrow that), keeps the loop's pid in `pid` (a dead or stale pid reads as stopped, which is what makes a container recreate harmless; the loop traps SIGHUP so a group-wide one, like claude-sched's, reaches only `run`) and `stop` kills the process group; `list`, `logs`, `restart`, `start-all` (skips `disabled`) as expected. `entrypoint.sh` runs `install-bundled` then `start-all` on every start. `CLAUDE_SERVICES_DIR` and `CLAUDE_SERVICES_BUNDLED` override the two directories (the tests use them).
  - **container/services/<name>/** — services shipped with the wrapper. `install-bundled` copies each into `~/claude/.services/<name>/` and marks it `.from-wrapper`; only marked copies are refreshed (keeping an existing `env`), so the repo stays the source without clobbering a user-written service of the same name. `usage-db`: `import.nu` (Nushell, `query db`) loads `~/.claude/usage.jsonl` into `usage.sqlite` (`samples`, unique on `ts, session_id`, resuming from the line count in `meta`; views `samples_left`, `cost_deltas` and `cost_per_day` are the series the readers share) and every assistant record of the transcripts under `~/.claude/projects` (`<session>.jsonl` and `<session>/subagents/agent-<id>.jsonl`) into `messages` (keyed on the API message id, since a streamed message is one record per content block; the four token counts, model, session and agent; each file read from the byte offset recorded in `transcripts`, whole lines only; `nu import.nu transcript <file>` does one file, which is what `container/usage-hook.sh`, the managed Stop/SubagentStop/SessionEnd hook, runs in the background for the transcript named in its input, under the `usage.sqlite.lock` flock the service's own import takes), `agent_runs` (one row per session from `claude agents --json --all`, upserted each import) and `events` (`ts, source, kind, detail, session_id`: the `started`/`done`/`failed`/`stopped` state changes the import sees between runs; the first import only backfills; `USAGE_AGENTS_JSON` names a file to read instead of running `claude`), and `forecast.py --persist` appends to `mode_history` (mode, proposal, override, slots, reason, used and projected percentages) when one of the discrete fields changed and at least hourly; priced by the `message_costs` view from `prices` (USD per million tokens by model-family prefix with a `since` day, brought in line with the `PRICES` table at the top of import.nu on every service import, so that is the one place to edit); `serve.py` (python stdlib; `run` installs `python3` into the default Nix profile once if it is missing) draws the last 7 days as inline SVG on `127.0.0.1:$PORT` (8420) and serves `/data.json`; `forecast.py` (stdlib, shared by serve.py and `claude-usage forecast`) computes the forecast from `usage.sqlite` and `~/.claude/history.jsonl` (burn rates from the running maximum of the used percentages per window, Manager-vs-agent split by transcript cost, projection to both resets, the Prime's weekday x hour activity profile and the budget reserved for it, the resource mode (`burn`/`normal`/`frugal`/`hold` from the projections at both resets by the `MODE_*` table at the top of forecast.py, with a tolerance and a minimum dwell against flapping and a one-step lift late in the 7d window when it projects well under the limit; the proposal is kept in `mode-state.json`, the Manager's `claude-usage mode set <mode> reason "<text>" for <duration>` override in `mode-override.json`, both next to `usage.sqlite`; `claude-usage mode` shows the effective mode and `mode clear` drops the override), agent slots 3/2/1/0 by mode, capped by the 7d pace (lifted to 1/2/3 when the projected 7d use at the reset is under 80/65/50%, still capped by the mode, so an unspent week is used; `slots_reason` says which rule applied) and 0 under 25% of the 5h window left, leftover burn in the last hour of a 5h window), drawn on the page's Forecast section and served at `/forecast.json` (`mode`, `mode_proposed`, `mode_override`, `slots`; every computation by the service also writes the small `mode` file `<mode> <override|-> <epoch> <slots>` that the status line reads, and `run` refreshes it after each import); `run` imports on start and every `INTERVAL` seconds; its links are relative so the page also works under the proxy's `/usage-db/`. `graphs`: Grafana (installed into the default Nix profile once by `run` if missing, pinned until `nix profile upgrade`) on `127.0.0.1:8423`, so http://127.0.0.1:8080/graphs/ through the proxy, configured only by `GF_*` variables exported in `run` (`serve_from_sub_path` with a `root_url` ending `/graphs/`, which Grafana serves itself under `/graphs/`, so the service has a `keep-prefix` marker and the proxy passes the path unstripped (stripped, Grafana redirected `/` to `/graphs/` forever); anonymous Viewer with the login form and Grafana's own basic auth off, since the proxy's basic auth is the gate and its forwarded `Authorization` header would otherwise be checked as a Grafana login and refused; no analytics, update checks or plugin admin; data, logs and plugins under `~/claude/.services/graphs/`). The SQLite datasource plugin (`grafanaPlugins.frser-sqlite-datasource`, loaded unsigned) is built once into a GC-rooted `plugins/frser-sqlite-datasource` link. `provisioning/datasources/usage.yaml` opens `usage-db/usage.sqlite` as `file:<path>?mode=ro` (never immutable: the importer keeps writing; usage-db's journal is the default rollback one, not WAL, so readers hold a shared lock only for a query and create no `-wal`/`-shm` files), `provisioning/dashboards/usage.yaml` loads `dashboards/*.json` (`overview`, the home page: budget left, 24 h cost, agent share and the main charts; `ledger` cost by model, directory and session; `rhythm` activity by hour and weekday; `cache` hit share and savings; `agents` subagent runs; `modes` mode timeline and time per mode, proposed vs effective, agent outcomes and failure rate, slots vs projected 7d use; and `budget`, `cost`, `tokens`, `share`, all linked to each other by the `usage` tag; 30 s refresh, shared tooltip crosshair, UTC, not editable, so change the JSON here), whose queries filter `ts` (epoch seconds) with `$__from/1000` and `$__to/1000`. `install-bundled` copies subdirectories (replacing them whole) besides files. `status`: `serve.py` (python stdlib, port 8421, so http://127.0.0.1:8080/status/ through the proxy) is one auto-refreshing page (meta refresh, 30 s; light/dark by `prefers-color-scheme`) and `/status.json` with the same data: agents (`claude agents --json`), services (`pid` files checked against `/proc`, linked as `../<name>/` when they have a `PORT`), `sched/schedules.nuon` (read through `nu`), open issues of `desocketed/context` by state label (`gh issue list`, cached 2 minutes; `STATUS_ISSUES_REPO` overrides the repo) and a usage summary and the resource mode from usage-db's `/forecast.json`; a source that fails shows its error in its section instead of breaking the page. `proxy`: Caddy (installed into the default Nix profile once by `run` if missing, so later starts are instant and offline but stay on that version until `nix profile upgrade`) on `127.0.0.1:8080` with its admin API on `127.0.0.1:2019` (`CLAUDE_PROXY_ADMIN` overrides it; the tests set it so they can never load into the real proxy); `services.sh` regenerates `~/claude/.services/proxy/Caddyfile` after every `start`, `stop`, `restart` and `start-all` (`proxy-config` does it on demand): a `handle_path /<name>/*` reverse proxy (`handle`, path kept, when the service dir has a `keep-prefix` marker) for each running service whose `env` has a `PORT` (the proxy excluded), an index of links at `/services/` (and at `/` when no `dashboard` runs; the `dashboard` service, whose PORT is not given a `/dashboard/` route, takes `/` with a catch-all reverse proxy), and the file is POSTed to the admin API's `/load` when the proxy is running. Everything behind it is under HTTP basic auth from `proxy/users` (`user hash` lines, mode 600, written by `claude-services proxy-password [user]`, which hashes a password read from the terminal or stdin with `caddy hash-password`); without that file the Caddyfile is a single 403 saying to run it. The direct `127.0.0.1:<port>` of each service stays open. The user opens `c port open 8080:8080` once for all services. `dashboard`: Glance (installed into the default Nix profile once by `run`, like caddy) on `127.0.0.1:8422`, configured by `glance.yml` (`${PORT}` from `env`), served by the proxy at `/`; custom-api widgets render the status service's `/status.json` (services with links, agents, resource `mode`/`slots`/`mode_override` when present, open issues by state) and usage-db's `/forecast.json` (5h/7d used, projection at reset, hours left). Links are relative so it works at the proxy root. `scheduler`: `serve.py` (python stdlib, port 8424, so http://127.0.0.1:8080/scheduler/ through the proxy; no model, no `claude` calls). Small objects with one job each: `Cron.next_after(ts)` (5 numeric fields, local time, vixie day-of-month/day-of-week rule), `Table.load()` (`schedules.nuon` through `nu`), `Forecast.get()` (usage-db's `/forecast.json`), `ResetAlarms` (the two forecast alarms per 5h reset: `leftover-burn` 50 minutes before it, only when the reset was more than 55 minutes away when first seen, and `window-open` 5 minutes after it, only with `slots` >= 1; an alarm found more than 10 minutes late after a downtime is dropped), `Heartbeat.read()`, `Ledger.record()` (writes), `History.recent()` (reads), `StateFile`, `Scheduler` acting on a `Book` of state (`reload`, `run_due`, `sleep_seconds`, `fire_alarm`, `fire_table`; slow fetches happen outside the `Book`'s lock) and the read-only `Report` (`next`, `health`, `recent`) over the same `Book`; the HTTP layer only renders. It sleeps until the nearest fire (at most 60 s, for the forecast), reloads the table on SIGHUP (`claude-sched` sends it after every change; a failed read keeps the old table) and, per fire, writes one JSON line `{"ts","alarm","msg"}` to `~/claude/.services/scheduler/events` (what the Manager's `tail -F` Monitor reads, see `manager/CLAUDE.md`), a record to `history.jsonl` (`ts`, `name`, `msg`, `missed`, `listener_age_s`, `manual`) and an `events` row (`source` `scheduler`, `kind` `fire` or `missed`, `detail` the alarm name) in `usage-db/usage.sqlite` (2 s busy timeout, skipped with a log line when the file is missing). The heartbeat is the mtime of `scheduler/listener`, touched by that Monitor and never by the service; older than 3 minutes (or absent) is stale, and a fire then is `missed`. A table entry with `budget` is skipped when less than that is left of the 5h window; `catchup once` replays one fire missed while the service was down (`state.json` keeps the last time seen and the planned resets); headless entries become a message asking the Manager to start the background session. The page (`/`: upcoming alarms with countdowns, the last 50 fired or missed, heartbeat state, uptime, a "fire now" button per alarm and table entry) and `/health.json`, `/next.json`; `POST /fire/alarm/<leftover-burn|window-open>` and `/fire/table/<name>` (header `X-Fire: 1`) fire one now. `SCHEDULER_DIR`, `SCHEDULER_TABLE`, `SCHEDULER_DB`, `SCHEDULER_FORECAST_URL`, `SCHEDULER_NOW` and `SCHEDULER_SPEED` (a test clock) override the defaults. `emacs`: Claude's own Emacs as a daemon (`emacs --fg-daemon --init-directory=/opt/claude-wrapper/emacs`), shipped with a `disabled` marker (`install-bundled` copies `disabled` on the first install only, so removing the marker sticks); `claude-services start emacs` starts it. `run` installs `container/emacs/emacs.nix` into the default Nix profile once (`nix profile install --expr`: `emacs-pgtk` with evil, evil-collection, which-key, vertico, orderless, marginalia, consult, magit, markdown-mode, diff-hl, doom-modeline, nerd-icons, hl-todo, vi-tilde-fringe, nix/nushell/just modes and the user's treebundel fork (built from its pinned `transient` branch), plus ripgrep, JetBrains Mono, DejaVu, Noto emoji and Nerd Font symbols for `fonts.conf` and the rose-pine cursor theme), then execs the daemon with its socket at `~/claude/.services/emacs/socket/server`, which the host reaches by that same path since `~/claude` is a shared bind mount and the container's root is the host user. Its `env` points `WAYLAND_DISPLAY` at `/run/claude-wayland`, where `run.nu` mounts the host's `$XDG_RUNTIME_DIR/$WAYLAND_DISPLAY` (skipped with a warning when unset; a compositor restart leaves the mount stale until `--restart-container`), so pgtk frames open on the user's display; `XDG_RUNTIME_DIR` is `/tmp/claude-0/run` for GTK. `container/emacs/`: `early-init.el` moves `user-emacs-directory` to `~/claude/.services/emacs/state/` (the init directory is the read-only checkout mount), `init.el` is the config (every package optional, so a bare Emacs loads it; mirrors the user's Doom config in `_tools/dotfiles/doom`: modus-vivendi, relative line numbers, scroll-margin 10, doom-modeline, evil with `SPC` leader and their bindings, vertico/consult, magit, treebundel over `~/claude` on `SPC p`), `claude.el` the commands `bin/claude-emacs` sends with `emacsclient -e`: `open <file> [<line>]`, `diff <a> <b>`, `report <file> [title <t>]` (read-only buffer), `ask <text> [timeout <s>]` (a `*claude ask <id>*` buffer per question, so concurrent asks stay apart, where `C-c C-c` submits and `C-c C-k` declines, written to `answers/<id>`; the CLI polls only its own file, clears leftovers older than a day, and exits 1 on decline, 3 on timeout, default 10 minutes, after marking the buffer timed out so a late answer is not delivered), `say <text>`, `ping` (exit 2 with the fix when the socket is missing). Inside the container run it as `nu ~/claude/_tools/claude-wrapper/bin/claude-emacs`.
- **run.nu** — first `bootstrap`: with a required tool missing from PATH it `exec`s `nix shell path:<checkout>#deps -c nu <itself>` with its own argv (read from `/proc/self/cmdline`, since top-level Nushell code has no argv), with `CLAUDE_WRAPPER_FLAKE` set in that environment so it happens once; it is skipped when that marker is already set (the `nix run` wrapper sets it too) or it is inside a container (where host-only's error is the useful one). Then it starts `claude-manager` in the background if it isn't running (removing a stopped one left over first: containers are kept after exiting so their exit code can be read), then attaches to its Zellij session. `--restart-container` stops and removes the running one.
  - Mounts: `~/claude` rw at the same path; Claude state from `~/.local/share/claude/{claude,claude.json,gh,git,scratch}` at `~/.claude`, `~/.claude.json`, `~/.config/gh`, `~/.config/git` (a directory, since git rewrites its config by rename, which a file bind mount refuses) and `/tmp/claude-0`; the host's `/etc/localtime` (symlink resolved) read-only plus `TZ=<zone name>` from where it resolves to (the container's own `/etc/localtime` is a symlink to `Etc/UTC`, so the mount only replaces that zone's data and programs that go by the zone name, like Node, would stay in UTC), so the container keeps the host's timezone; the notify proxy socket; the Wayland socket at `/run/claude-wayland` for the `emacs` service; the `claude-nix` and `claude-code` volumes. Wrapper config in `~/.config/claude` is never mounted.
  - `plan` only builds podman arguments and the directories/files to create (including `~/claude/.services`); `prepare` applies them (and seeds `~/claude/CLAUDE.md` from `manager/CLAUDE.md` if missing) only when a container is actually being started, so `--dryrun` stays exact.
  - Right after creating a new container it runs `mounts apply` and `ports apply` so saved mounts and relays come back.
- **manager/CLAUDE.md** — the operating guide for the Manager session, copied to `~/claude/CLAUDE.md` on first start. Edit it here; an existing copy in `~/claude` is never overwritten.
- **lib/** — Nushell modules used by run.nu through their exported commands: `ns.nu` (wraps `podman unshare claude-ns`), `clone.nu`, `mounts.nu`, `ports.nu` (each relay is a transient systemd user unit `claude-port-<in|out>-<proto>-<host>-<container>`), `hints.nu` (parses the keybinds in `zellij/config.kdl` and renders the status bar hints and the Ctrl+Space ? cheat sheet from them).
- **ns/** — `claude-ns`, a Zig helper run under `podman unshare`: `mount`/`unmount` bind mounts into a running container's mount namespace and `relay` TCP/UDP between the host and container network namespaces (an optional trailing bind address, IPv4 only, puts an inbound relay's host listener on something other than 127.0.0.1).
- **bin/claude-screensaver, container/screensaver, container/screensavers/<author>/<name>** — Ctrl+Space S runs `bin/claude-screensaver-tab`, which opens `zellij/screensaver.kdl` (a tab with no status bar) running `claude-screensaver`, then returns to the tab you came from (`go-to-tab-name`) and the tab closes. The launcher takes `[name|list]` and, on the host, `podman exec`s `container/screensaver` (`/opt/claude-wrapper/screensaver` in the container, where the services the screensavers read are). That runner puts the terminal on the alt screen with a hidden cursor, runs a random (or the named) executable from `screensavers/<author>/` (the runner is generic; each author keeps their designs in their own directory) with stdin on `/dev/null`, quits on any key or SIGINT/SIGTERM and restores the terminal. A screensaver is just an executable that draws until it is killed (re-read the terminal size each frame; SIGWINCH needs no handling); `tally/abacus` (python3 stdlib) is Tally's ledger: beads on wires rest at live counts from the `status` and `usage-db` services, refreshed every 30 s, and the wires settle at 0 and say "offline" when a service is down.
- **zellij/** — host-side Zellij config and layout. `run.nu` sets `CLAUDE_CONTAINER` and puts `bin/` on PATH before starting Zellij, so panes inherit both. The layout's first pane `podman attach`es to Claude; `default_shell` is `bin/claude-container-shell`, so every new pane or tab is a shell inside the container.
  - Ctrl+Space U runs `bin/claude-update` in a floating pane: `just update`, then `run.nu --restart-container --detach` from `~/claude` (via `CLAUDE_WRAPPER_ARGS`/`CLAUDE_WRAPPER_DIR`). It records `running|done|failed <time>` in `CLAUDE_WRAPPER_UPDATING`, which `bin/claude-attach` uses to reattach the claude pane when an update ended its attach. The same pane runs `claude-update` itself when the container exits 75, an update requested from inside it. It tees all output to `~/claude/.services/update/update-<time>.log` (last 5 kept); on failure it writes `last-failure` there (state, time, error, last 40 lines); a success removes a stale one. The next `container/start.sh` points the Manager at it in the fixed first prompt, ahead of the arm-the-monitor sentence (the text is untrusted output, never embedded), and renames it `last-failure.seen`. There is no way to message a running session from the host, so a failure that leaves the old container running is only seen at its next start.
  - The status line is zjstatus. `layout.kdl` is a template: at every launch `run.nu` renders the `mode_*` hint strings derived from the keybinds in `config.kdl` in place of its `// hints` line, saves the result as `$XDG_RUNTIME_DIR/claude-wrapper-<name>.layout.kdl` (`/tmp/claude-wrapper-<uid>` without a runtime dir) and passes that to `--default-layout`, so the hints can't drift from the bindings. `bin/zellij-mode-hints --print` shows the hint lines, `--layout` the rendered layout. Ctrl+Space ? runs `bin/claude-wrapper-keys`, a multi-column cheat sheet of every mode's keybinds from the same data. The labels come from the action-name tables at the top of `lib/hints.nu`; add an entry there when a new action's generated label reads badly.
  - Keybinds are vim-like and modal: Zellij starts in `locked` (insert), `Ctrl Space` enters `tmux` mode as a normal mode, `Esc`/`i` return. They replace Zellij's defaults (`clear-defaults=true`), so every mode used must be bound in full.
- **flake.nix** — packages `run.nu` with its host-side dependencies as a wrapper that sets `CLAUDE_WRAPPER_FLAKE=1`, and exposes them alone as `packages.deps` (a `buildEnv`), which `run.nu` fetches on its own when one is missing. Flakes only see git-tracked files: `git add` new files before `nix build`/`nix run`.
