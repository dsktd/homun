# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A launcher that runs one persistent "Manager" Claude Code session in a Podman container named `claude-manager`, driven from a Zellij session of the same name on the host. The container only sees `~/claude`, a treebundel workspace root (`~/claude/.bare/<repo>.git` bare clones, `~/claude/<workspace>/<repo>` worktrees), plus whatever the user mounts in later with `c mount`.

## Commands

- `nix run . -- [flags]` or `nix profile install .` — the `claude-wrapper` launcher, with Nushell, Zellij, xdg-dbus-proxy, just, git and `claude-ns` provided by the flake. Podman and systemd come from the host.
- `./run.nu [flags]` — the same launcher without Nix (needs those tools on PATH). It's a Nushell script (`#!/usr/bin/env nu`), not POSIX shell.
- `just install [name] [dir]` — symlink `run.nu` as `~/.local/bin/c` (by default); an existing non-symlink is moved to `<name>.bak`.
- `just build` / `./run.nu --build` — build the container image (`podman build . -t claude`); `just update` (used by Ctrl+Space U) is the same cached build; `just refresh` rebuilds with `--no-cache` to pick up new Debian packages. Claude Code is not in the image and updates itself.
- `./run.nu -R` — replace the Zellij session (layout changes only apply to new sessions); `--restart-container` also recreates the container so a new image applies. `-s` opens a shell, `-d` only starts the container, `-Z` attaches without Zellij.
- `./run.nu --dryrun` — print the planned disk changes and podman arguments without touching anything.
- Host-only subcommands (they refuse to run inside a container):
  - `c clone <url> [name]` — bare-clone a repo into `~/claude/.bare/<name>.git`.
  - `c mount <path> [--rw]`, `c unmount <path>`, `c mounts` — bind host paths into the running container at the same path (read-only by default), saved in `~/.config/claude/mounts.nuon`.
  - `c port open <host>:<container>[/tcp|/udp] [--from-host]`, `c port close <spec> [--from-host]`, `c ports` — relay ports between host and container localhost, saved in `~/.config/claude/ports.nuon`. Without `--from-host` the host's port reaches the container; with it the container's port reaches the host.
  - `c usage [--since <duration>] [-n <rows>] [-w <width>] [--json]` — summarise `~/.local/share/claude/claude/usage.jsonl` (the samples statusline.sh appends): latest budgets, a table of the last samples and per-day sparklines of the 5-hour, 7-day and context budgets left. Runs `bin/claude-usage`, which also works inside the container against `~/.claude/usage.jsonl`.

`just test` (`nu tests/run.nu`) lints every script and drives run.nu's subcommands, `container/start.sh` and `bin/claude-attach` in a throwaway HOME against `tests/fake` standing in for `podman`, `systemd-run`, `systemctl`, `git`, `claude` and `claude-update`, asserting on the calls they log. `container/request-update.sh` is tested end to end with start.sh as PID 1 under `unshare -Urpf --mount-proc` (skipped where user namespaces are unavailable). `CLAUDE_WRAPPER_CONTAINERENV` points `host-only` at a different marker file, so the suite also runs inside the container. Run it after every change.

## Architecture

- **Containerfile** — Debian image with git, gh, nix, notify-send and Nushell (a pinned static release tarball in `/usr/local/bin`, since `/nix` is a volume at runtime; `SHELL` and root's login shell). Tools installed with `nix profile install --profile /nix/var/nix/profiles/default <pkg>` land in the persistent `claude-nix` volume and are on PATH in every container. The scripts that run inside the container live in `container/`, copied to `/opt/claude-wrapper` in the image (ENTRYPOINT, CMD and the managed status line point there); `run.nu` bind-mounts the checkout's `container/` read-only over that copy, so edits apply on the next container start (the status line on its next refresh) without a rebuild, while the image's copy keeps it usable without the launcher. Claude Code is not in the image: `container/entrypoint.sh` runs the official installer on first start (under a `flock`, so concurrent starts are safe) into the shared `claude-code`/`claude-code-bin` volumes (`~/.local/share/claude`, `~/.local/bin`), where its own auto-updater maintains it. On every start it also installs Nushell into that default profile if missing, and seeds the persisted global git config (`~/.config/git/config`, which `prepare` pre-creates so `--global` picks it over an absent `~/.gitconfig`) with a git identity from the gh login (`<login>@users.noreply.github.com`) when it has none. The container's main process is `container/start.sh` (the image's CMD): it opens Claude on the screen the user last typed in (a background job via `claude attach`, or that conversation via `--resume`), falling back to `claude --continue || claude`. It reads the last `history.jsonl` entry and `~/.claude/jobs/<id>/`, which are Claude Code internals, so it is the first thing to check when an update changes startup behaviour.
- **container/request-update.sh** — what the Manager runs to update from inside: SIGUSR1 to PID 1 (start.sh traps it and exits 75 once the foreground Claude has returned, instead of starting another), then SIGTERM to every other process in the container. It refuses while PID 1 is still `entrypoint.sh` (installing Claude Code), where there is no trap yet. `bin/claude-attach` reads the 75 with `podman inspect` from the stopped container (`run.nu` starts it without `--rm` because `podman attach` returns 0 whatever the container exited with), runs `claude-update` and reattaches like after Ctrl+Space U (or exits 75 itself when run outside a Zellij session, where there is no `claude-update`).
- **container/statusline.sh** — the status line (`🤖 manager` badge, model, context left, rate limits left). It also appends throttled usage samples (rate limits, context, cost) to `~/.claude/usage.jsonl` for graphing; per-session throttle state is in `~/.claude/usage/`.
- **run.nu** — starts `claude-manager` in the background if it isn't running (removing a stopped one left over first: containers are kept after exiting so their exit code can be read), then attaches to its Zellij session. `--restart-container` stops and removes the running one.
  - Mounts: `~/claude` rw at the same path; Claude state from `~/.local/share/claude/{claude,claude.json,gh,git,scratch}` at `~/.claude`, `~/.claude.json`, `~/.config/gh`, `~/.config/git` (a directory, since git rewrites its config by rename, which a file bind mount refuses) and `/tmp/claude-0`; the notify proxy socket; the `claude-nix` and `claude-code` volumes. Wrapper config in `~/.config/claude` is never mounted.
  - `plan` only builds podman arguments and the directories/files to create; `prepare` applies them (and seeds `~/claude/CLAUDE.md` from `manager/CLAUDE.md` if missing) only when a container is actually being started, so `--dryrun` stays exact.
  - Right after creating a new container it runs `mounts apply` and `ports apply` so saved mounts and relays come back.
- **manager/CLAUDE.md** — the operating guide for the Manager session, copied to `~/claude/CLAUDE.md` on first start. Edit it here; an existing copy in `~/claude` is never overwritten.
- **lib/** — Nushell modules used by run.nu through their exported commands: `ns.nu` (wraps `podman unshare claude-ns`), `clone.nu`, `mounts.nu`, `ports.nu` (each relay is a transient systemd user unit `claude-port-<in|out>-<proto>-<host>-<container>`), `hints.nu` (parses the keybinds in `zellij/config.kdl` and renders the status bar hints and the Ctrl+Space ? cheat sheet from them).
- **ns/** — `claude-ns`, a Zig helper run under `podman unshare`: `mount`/`unmount` bind mounts into a running container's mount namespace and `relay` TCP/UDP between the host and container network namespaces.
- **zellij/** — host-side Zellij config and layout. `run.nu` sets `CLAUDE_CONTAINER` and puts `bin/` on PATH before starting Zellij, so panes inherit both. The layout's first pane `podman attach`es to Claude; `default_shell` is `bin/claude-container-shell`, so every new pane or tab is a shell inside the container.
  - Ctrl+Space U runs `bin/claude-update` in a floating pane: `just update`, then `run.nu --restart-container --detach` from `~/claude` (via `CLAUDE_WRAPPER_ARGS`/`CLAUDE_WRAPPER_DIR`). It records `running|done|failed <time>` in `CLAUDE_WRAPPER_UPDATING`, which `bin/claude-attach` uses to reattach the claude pane when an update ended its attach. The same pane runs `claude-update` itself when the container exits 75, an update requested from inside it.
  - The status line is zjstatus. `layout.kdl` is a template: at every launch `run.nu` renders the `mode_*` hint strings derived from the keybinds in `config.kdl` in place of its `// hints` line, saves the result as `$XDG_RUNTIME_DIR/claude-wrapper-<name>.layout.kdl` (`/tmp/claude-wrapper-<uid>` without a runtime dir) and passes that to `--default-layout`, so the hints can't drift from the bindings. `bin/zellij-mode-hints --print` shows the hint lines, `--layout` the rendered layout. Ctrl+Space ? runs `bin/claude-wrapper-keys`, a multi-column cheat sheet of every mode's keybinds from the same data. The labels come from the action-name tables at the top of `lib/hints.nu`; add an entry there when a new action's generated label reads badly.
  - Keybinds are vim-like and modal: Zellij starts in `locked` (insert), `Ctrl Space` enters `tmux` mode as a normal mode, `Esc`/`i` return. They replace Zellij's defaults (`clear-defaults=true`), so every mode used must be bound in full.
- **flake.nix** — packages `run.nu` with its host-side dependencies. Flakes only see git-tracked files: `git add` new files before `nix build`/`nix run`.
